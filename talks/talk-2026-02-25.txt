│ Context                                                                      │
│                                                                              │
│ Go 手写 parser 使用自研递归下降框架，db.New() 开箱 (depth+1)，db.Wrap() 包箱 │
│  (depth-1)。                                                                 │
│ 需要验证：从 f_top 入口出发，所有可能执行路径结束时 box depth == 0。         │
│ 单个 f_xxx 函数内部允许不配对（如 New 多于 Wrap），只要整体路径配对即可。    │
│ 遇到 panic() 的路径丢弃不分析。                                              │
│                                                                              │
│ 技术方案                                                                     │
│                                                                              │
│ 核心思路：抽象解释 + 不动点迭代                                              │
│                                                                              │
│ - 抽象域：DeltaSet = 一组可能的 depth 变化量整数集合                         │
│ - 每个函数计算一个 summary（所有路径的可能 delta 集合）                      │
│ - 用 worklist 算法做函数内 CFG 数据流分析                                    │
│ - 用 SCC + 不动点迭代处理函数间递归调用                                      │
│ - 循环处理：CFG 自然形成环，worklist 迭代至收敛；加 widening 防止发散        │
│                                                                              │
│ 递归处理                                                                     │
│                                                                              │
│ f_1 -> f_2 -> f_1 的情况：初始 summary 为                                    │
│ BOTTOM（不可达），迭代展开基础情况的 delta，                                 │
│ 直到 summary 稳定。对于正确的递归下降 parser（如 New, f_expr, Wrap），       │
│ 递归调用 delta=0，2-3 轮即收敛。                                             │
│                                                                              │
│ For 循环处理                                                                 │
│                                                                              │
│ CFG 建模为 loop_head -> body -> loop_head 的环 + loop_head -> loop_exit      │
│ 的跳出边。                                                                   │
│ - 0 次迭代：直接走 loop_exit                                                 │
│ - 1+ 次迭代：body 的 delta 通过环累积，worklist 自然处理                     │
│ - 若 body delta != 0，累积后 delta 集合持续增长，widening 到 TOP（报错）     │
│ - break 跳到 loop_exit，return 跳到函数 exit                                 │

● CFG 看起来正确。问题是递归函数 f_expr 调用自身，初始 summary 是
  BOTTOM，compose(BOTTOM) = BOTTOM，所以永远不会收敛到非 BOTTOM。

  问题在于 compose 方法：当 callee summary 是 BOTTOM 时，compose 返回
  BOTTOM，这意味着整个路径被认为不可达。但对于递归函数，初始 BOTTOM
  应该在迭代中被打破。

  关键问题：f_expr 调用自身，summary 初始为 BOTTOM。当分析 f_expr 时，遇到
  call:f_expr，compose(cur, BOTTOM) = BOTTOM，所以后续的 Wrap
  节点永远不可达，exit 也不可达。

  解决方案：对于 SCC 内的递归调用，初始 summary 应该用 {0}（identity）而不是
  BOTTOM，或者在 compose 时对 BOTTOM callee 特殊处理——当 callee 在当前 SCC 中且
  summary 是 BOTTOM 时，跳过该调用（假设 delta=0）。
